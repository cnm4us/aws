The user-confirmed publication model governs this plan:

| Creator's chosen destination for the same video | Publication identity and reporting behavior |
| --- | --- |
| Group A | Its own publication ID; Group A's reporting rules/context and caller-owned Sent state. |
| Channel B | Its own publication ID; Channel B's reporting rules/context and caller-owned Sent state. |
| Global | Its own publication ID from explicitly choosing Global; Global's reporting rules/context and caller-owned Sent state. |

Choosing Group A alone does not publish to Global. Choosing Group A + Channel B + Global creates separate destination publications, even when they share a production/media asset. A viewer may access the Global publication while being unable to enter Group A; Global reporting neither checks that other publication's access nor inherits its rules, report state or moderation attribution.

These are source findings and a user-confirmed product contract, not a live data audit, exploit claim, API test result or physical layout measurement. No reports, database contents or moderation settings were changed during investigation.

## Locked Decisions and Proposed Native Defaults

The user approved implementation of the following native decisions.

1. Add the flag to the selected playable publication's right control lane in Global/personal/group/channel. Reuse the web outline/filled orange glyph and Flag/Sent caption, with Report video/Report already sent accessibility labels. Reserve a constant row and include its full height/gap in the scrollable lane budget: status resolution must not move avatar, Like, CC or sound. Place after CC when present and before sound. Preserve at least44-point tap targets and short-stage/larger-text scrolling.
2. Submission requires sign-in, matching web policy. Anonymous Global may open an overlay with Sign in to report and Close. Sign in uses existing Account navigation, discards old report state on identity change and never submits automatically or moves a draft between accounts. Normal browsing remains usable. Showing the flag does not require a separate status request.
3. Bind every operation to API origin, account/auth generation, feed visit, explicit context and exact publication ID. Derive reporter/space/production/scope/rule version server-side and reject unexpected authority fields. Global, Group and Channel publications of the same production have separate publication IDs, drafts and Sent state. Reporting one does not report or mark another Sent. Shared media/production identity never replaces publication identity.
4. Space routes require current destination-space viewing and exact eligible publication selection. Global routes require an eligible publication belonging to the server-resolved Global destination. Global reports use Global's configured reporting rules/context and global scope; Group/Channel reports use their own destination's rules/context and space_culture scope. Resolve attribution from the actual publication, with consistent Global identity/alias handling. Access to a different destination's publication is irrelevant, and reporting grants no membership.
5. Preserve active user-group/default-rule mappings and reporter-visible rules. Initial groups come from the target publication destination's culture configuration, including Global's own configuration for a Global publication. Retain the existing ordinary all-active catalog behavior when that destination has no curated initial groups, plus inline Show All with existing ordering. Neither behavior depends on access to a different publication space; there is no source-space fallback. Do not inherit another destination's curation or expose private/admin-only rules, invented categories or active Submit for an unmapped group.
6. Use one transparent native Report screen with one80% black scrim, safe-area header/title and fixed upper-right Close. Loading/error/empty/confirmation/detail live in that screen; lost authorization is fully opaque. Local Back exits detail/expanded group while retaining valid edits. Covered feed is paused, silent, noninteractive and absent from accessibility focus. Close restores the same video/time and prior pause/playing intent only while authorized, with no feed replacement or additional player.
7. Preserve group-default Submit and explicit mapped-rule Submit. Browsing never submits. Label each action with its reason, disable all submits while one is pending, and announce confirmed success. Success marks only the bound publication Sent and closes. Sent reopens the caller's recorded reason/time and explanations without another submission or public count. No free-text note field in this port.
8. Whole video is the default: optional Start/End are both unset. Provide editable `mm:ss` fields, explicit Clear and Use time when flagged shortcuts using the captured paused position. Support long-minute/hour values through a tested parser. Each field remains independently optional as on web; equal endpoints are valid, end before start is not. Validate finite nonnegative whole seconds, representable storage bounds and known duration; never seek/play hidden media to choose a range. Server normalizes authoritatively and returns stored times for honest confirmation. Test edited-production/upload-duration disagreement.
9. Render Long/Allowed/Disallowed using bounded native text/structured blocks projected from the existing restricted Markdown fields. Preserve headings, paragraphs, lists/examples and link labels/targets without remote image loads or HTML execution. No WebView/token-bearing embedded browser. Empty tabs state that no examples exist. Inspect legacy HTML-only content in Phase A and provide safe text fallback rather than silently dropping explanations.
10. Preserve unique publication+reporter and existing moderation review routing. Timeout/disconnect/cancellation/5xx can occur after a commit: never auto-resend. Reconcile with the exact caller-owned report read; existing report becomes Sent, confirmed absence permits another deliberate Submit, failed reconciliation remains uncertain. Only explicit already_reported409 starts duplicate reconciliation; arbitrary409 is not success. Changed rule/configuration requires refreshed options.
11. Draft/status storage is bounded, in-memory and account-specific. Keep unsent reason/time edits only for the same eligible feed visit/publication on Close/reopen, at most the original60s verification window and20 drafts. Clear on success, publication/feed replacement, background, expiry, access loss or identity change. Confirmed Sent markers are capped at200 entries with original freshness, seeded from validated caller-owned feed data; failed reads never turn Sent into false. Uncertain-write markers can survive ordinary modal Close until read reconciliation, without retaining private draft content; identity replacement clears them.
12. Use shared account/access management and independent45s quiet renewal/60s hard expiry while the report screen is active. Expiry/background hides stale options/detail and disables submission; server revalidates writes. No neighbor preload or swipe-time options polling.401 invalidates the current account; definite publication/space loss masks that scope; unavailable reasons/rules, bad ranges and transient reporting failure leave playable media usable. Preserve build33 spacing/rings, creator/date/story/captions, entry cover, bookmarks and maximum3 players.

## Proposed API and Data Contract

New paths are relative to `/api/viewer/v1`: resolveViewer with required authentication, no-store, strict scalar positive safe IDs, no unexpected query/body fields, bounded JSON, existing cookie CSRF and mixed-auth rejection, sanitized reporting-specific errors. Legacy browser routes remain compatible.

| Method / path | Behavior |
| --- | --- |
| GET `/feed/global/publications/:publicationId/reporting/options` | Signed-in reporter and exact eligible publication belonging to the server-resolved Global destination; Global's reporting choices, this publication's own report state and safe target identity. |
| GET `/spaces/:spaceId/publications/:publicationId/reporting/options` | Exact space/publication and current viewing, including authorized personal feeds. |
| GET either context prefix + `/reporting/groups/:groupId/rules/:ruleId` | Revalidate target and active reporter-visible group/rule mapping; return only current explanation/examples, without privileged guidance/history. Numeric IDs avoid trusting an arbitrary rule URL. |
| POST either context prefix + `/report` | Strict `{userFacingRuleId, ruleId?, reportedStartSeconds?, reportedEndSeconds?}`. Group required by native UI; omitted rule invokes server default resolution.201 returns bound confirmed reported state/normalized times. Explicit already_reported409 is reconciled by a subsequent read. |

Options DTO: `{context, publicationId, spaceId, reportedByMe, myReport, groups, initialGroupIds, durationSeconds}`. Send the all-active catalog once; initialGroupIds selects initial rows. Each group has label/description and ordered rule ID/slug/title/shortDescription/default association. myReport is only the caller's safe group/rule snapshot, recorded times/date, with no moderation notes/status or other reporters. For Global context, spaceId must be the resolved Global destination ID and publicationId must identify that destination's actual publication. A client context label or visible_in_global flag is insufficient. Native validates echoed target/context. Detail echoes target/group/rule/current version and bounded description/allowed/disallowed document fields.

Define field/array/body limits in Phase A and validate against actual catalog sizes; proposed maximum decoded reporting JSON is1MiB. Fail clearly rather than silently truncating rule text or options. Add native reportedByMe using the existing caller-owned SQL value, with missing-field compatibility during additive rollout. Sent hydration remains independent of media readiness; no options call on ordinary swipes.

## Backend Implementation Approach

- Introduce a small context-aware reporting authority/service/router alongside existing reports modules and mount under viewer routes. Share group/default-rule resolution, snapshots and insertion; no moderation-policy implementation in React Native.
- Extract common catalog/options projection from cookie-specific published-summary/space guards. Preserve browser defaults. Native Global/space routes use explicit destination identity plus exact-feed eligibility; recheck after options/detail reads and whitelist rule fields even for an admin reporter. The current Global selector alone does not prove destination identity.
- Before enabling reporting, trace explicit destination creation/publishing callers, visibility writers, normal/pinned Global selection and supported Global aliases. Record any mismatch with the user-confirmed model and define the smallest prerequisite correction with regression coverage. Never translate an incorrect Global row to a sibling publication, create a Global publication automatically or treat a visibility flag as consent to publish. Broader data migration, republication or moderation-policy changes require separate scope; no such mutation is authorized by this planning update.
- Native writes use a transaction/publication lock and current authority/mapping/version checks immediately before insertion. Thread the same connection through shared report helpers (insert currently always uses getPool). Add selector connection injection where needed (Global currently lacks it), preserving existing callers. Unique publication+reporter remains the concurrency backstop; roll back/release on failure. Avoid post-commit reads that misclassify a committed write as definite failure.
- Explicitly adapt browser snake_case versus native camelCase times. Locally map known reporting DomainErrors to ViewerApiErrors, particularly409. Separate invalid range/reason/rule-detail unavailable from actual target/access denial. Make client error copy reporting-specific; exclude optional rule-detail404 from broad space invalidation while retaining genuine access-loss handling.
- Project current authored rule Markdown/examples through a narrow native document converter, with safe legacy HTML text fallback. Never spread the browser's guidance/history DTO. No schema change expected; revise the plan if inspection establishes a real need.
