## Context

Plan175's uncommitted build16 adds shared browser/native creator-space Follow authorization and a contextual Creator-profile action. During phone acceptance the user confirmed no Global Follow and a reachable group-profile Follow/Unfollow action, but found no following-state indication after returning to the group feed. ### Product clarification during build16 acceptance

The user confirmed these product choices during build16 acceptance:

- Global introduces creators and spaces through creator-selected, broadly public-safe publication. Creators may publish mostly inside spaces. Space culture/moderation remains contextual; Global distribution has its own broader-audience moderation requirements. This revision does not change publication eligibility, moderation rules or age enforcement.
- Follow means this creator's **column in this space**. The same creator can have independent columns in different spaces. No Global Follow control is introduced; a historical Global-follow concept is not a commitment for this discovery path.
- Show visible Follow/Following state and a separate action alongside the creator avatar in group/channel feeds. Keep the avatar opening Creator profile and retain the profile's explicitly scoped card.
- Launch shows the source creator once above the space choices: public avatar, display name and profile bio. Each destination shows its group/channel name and a brief description introducing its community and moderation culture; do not invent a policy summary or repeat the creator profile for every row.
- Present Launch / Open in a space as a video overlay with an80% opaque black scrim, an upper-right existing-style Close button and a scrollable destination list. Retain the originating video underneath, paused and noninteractive. Close restores its previous position and playing/manual-pause state.
- An attempted contextual Follow with unmet joining/subscription requirements must explain the actual requirements and offer the next action: age verification, paid membership and/or administrator approval. Multiple requirements may apply. Membership, payment and approval are explicit actions, independent of the Follow relationship. Pending/blocked does not mean Following; completion requires fresh eligibility verification and an explicit Follow action.
- Restricted spaces need a permitted introduction/requirements surface before their protected feed. A space must control whether its existence and introduction are discoverable at all. Do not expose an undiscoverable private support group simply because a related creator/video exists publicly.

Inspection confirms build16 Launch lists only currently viewable group/channel destinations containing the **same production**; inaccessible destinations are filtered out. It does not discover every space where a creator publishes. Existing Follow also requires an eligible publication and generic denial cannot identify an age/payment/approval reason. The complete breadcrumb path therefore requires a later discovery/entry-policy contract rather than loosening either boundary. The follow-on specification below captures that work and its unresolved dependencies; it is not delivered by build16 or the immediate UI revision.

## Locked Decisions

Original server/lifecycle decisions remain in force. Placement and Launch presentation are revised below to reflect the agreed product direction; R1–R3 are implemented and host-qualified; E/F require the replacement binary and phone evidence.

1. **Follow is creator within space.** Store/read one existing `(follower,target,space)` tuple. Multiple eligible publications by the same creator in one space share Follow state/count; the same creator in another space is independent. A publication supplies current proof, not the relationship key. No production-level aggregation and no change to feed ordering or Spaces membership.
2. **Exact currently viewable source.** Every contextual Follow read/write authenticates the follower, loads the declared group/channel, denies Global aliases/settings representations, applies current `canViewSpaceFeed`, and selects the exact ordinary eligible publication. Derive target from selected `owner_id` as serialized in the feed; require a positive safe-integer, existing nondeleted creator. Legacy target path ID must match that target. Possession of a publication/creator ID or a Global projection is insufficient authority. The server validates declared context, not which screen an HTTP client actually viewed.
3. **Shared browser/native authority.** Strengthen existing Follow service routes, not just a native wrapper. Legacy routes gain required canonical `publicationId` query proof; update all three browser fetch sites in the same increment. Deny missing/repeated/unknown/malformed context. Browser Global cannot derive contextual Follow from item `spaceId`; render, request and handler guards use actual feed context. Preserve legacy successful summary fields and cookie CSRF. No contextless alternate write or follower-list exposure.
4. **Existing view policy, independent participation.** Public non-member group/channel viewers may follow visible creators when authenticated and allowed by current space view rules. Do not require membership, personal access or COMMENT_CREATE. Self summary returns actual scoped followersCount with `following:false,canFollow:false,disabledReason:'self'`; self writes reject consistently. Deleted/missing/mismatched creators are unavailable. Reuse existing applicable bans/visibility checks; no invented person-block/follow-enabled/posting-suspension system.
5. **Following grants no access.** Follow/unfollow does not insert membership, invitation, subscription, role or personal-access rows and does not change `personalEntry`. A profile's personal-entry action still uses its existing fresh independent check. Existing relationships remain stored after access loss; this contextual UI becomes unavailable. Managing an orphaned relationship without an eligible source is deferred, not a reason to weaken reads/deletes.
6. **Idempotent desired state and honest counts.** POST means following, DELETE means not following; duplicate requests must not duplicate a tuple or drift counts. Use the unique key and a coherent write/summary on one supplied connection, with near-write authorization and transaction/rollback where needed. Revalidate authority before returning protected data. Counts are derived, safe nonnegative integers, scoped only to target+space; no historical recount/repair or new counter column. Concurrent clients can change the same relationship; promise a confirmed snapshot, not a permanent state or global linearizability. Justify any locking/index change with actual SQL/concurrency evidence.
7. **Small native API.** Add GET/POST/DELETE `/api/viewer/v1/spaces/:spaceId/publications/:publicationId/creator-follow`. Target is server-derived, not accepted in body. Exact DTO described below; no emails, follower IDs, profiles, permissions internals, tokens or media fields. No native directory/count batch request. Strict route/query/body validation and no-store responses, sanitized errors, native bearer-only client transport and existing mixed-auth rejection; cookie writes on viewer paths still require CSRF.
8. **Visible scoped Follow and Global recognition.** In authenticated eligible group/channel feeds, use a44px separate plus beneath the avatar when not following here: gray for no relationship, yellow for following elsewhere only. Confirmed following here uses green/no plus; avatar opens profile, where written scoped state/count and Unfollow remain. Green takes precedence over elsewhere. Self has no write. Unknown/error/background/expired state is neutral with checking/retry as appropriate; no false confirmed state or fabricated count. Accessible labels/hints name the state and current space. Authenticated Global uses a selected-only read-only recognition boolean: yellow when following this creator in any group/channel, gray otherwise, never green or plus. Global profile still has no contextual Follow card; Launch still enters a specific space. Personal and anonymous viewing make neither contextual Follow nor recognition requests.
9. **Capture the actual tap context.** Add only scalar IDs and generation/visit data to a separate optional Follow proof on the Creator route/store: space, publication, expected creator and context generation. Capture it from the current selected feed item on tap, before any navigation transition to the retained outer origin. Check expected creator against both public profile and returned summary. A Creator opened from Global/personal gets no proof even if an outer Launch group or older creator origin exists. Returning from a personal detour to the original group Creator retains that original visit's proof, subject to revalidation. Never infer current Follow context from profile personalEntry, production, route return label or stale outer journey origin.
10. **One active bounded verification owner.** The active feed Follow action or contextual profile card validates account and exact Follow proof on entry/foreground; reuse `VerifiedRefresh` with45s quiet renewal and60s hard age measured from earliest relevant request start. Healthy renewal keeps confirmed UI stable. Coordinate with the existing feed access guard so only one owner performs routine account validation: reuse the existing feed authority/lease where possible and hand off to the profile card on focus. Keep exact Follow-proof renewal bounded separately without adding a second account clock. Release ownership on blur/background/disposal. No duplicate Feed mount or player. Hide/disable contextual fields on background, access failure/expiry or generation mismatch; generic failure is not proven denial. Public creator identity may remain visible under its existing contract. Recovered authority requires an explicit read before writes.
11. **Requests cannot escape their visit.** State binds API origin, auth generation, space, derived creator, source publication and visit generation. One mutation at a time; abort/ignore stale results on blur, new creator, close, foreground boundary, account switch/sign-out or context replacement. Mutations never extend the verification deadline by themselves. Confirm state/count only from a valid current response. After timeout/ambiguous result, clear uncertain state, disable further toggle and offer Refresh status; do not claim rollback, queue or automatically resend a mutation. Revisit/refocus performs a fresh read. Browser late responses receive equivalent scope guards.
12. **Playback and return stay owned.** Profile coverage continues to pause/release through the existing journey/coordinator. Follow/refresh cannot start audio, add players, reset playback position, change intentional pause or reset the Launch outer return. Preserve group → Creator → personal → profile → group → original Global. Follow authority denial is propagated to the matching retained feed/return guard where appropriate, without misclassifying a missing creator as an account failure or discarding the independently public profile.
13. **Evidence and distribution.** Build16 and its source manifest remain a historical candidate with partial phone acceptance. After revision implementation, choose the next actually available build number rather than assuming17, stamp source and verify export/archive/downloaded signed IPA before installation. Run affected final-source gates; do not reuse a build16 pass for changed code. Use owned disposable fixtures and exact restoration/session tracking; physical and controlled evidence remain distinct. No Plan175 commit/push is implied.
14. **State consistency without extra background work.** Bind confirmed state to API origin/account generation/space/creator, while retaining exact publication proof for each operation. On profile/feed return, explicitly reread current authority/state before enabling a write; a confirmed result may invalidate other views but is not a substitute for current authorization. Other publications by this creator in this space show the persisted relationship after their own current read; another space remains independent. Observe only the selected, eligible video; do not preload Follow summaries for the feed or retain an unbounded creator cache. Abort/ignore responses for previous selection, account, context or visit; one pending mutation per active relationship, no automatic resend after uncertainty.
15. **Launch is a retained-video overlay.** Use the existing Comments transparent-modal/fade approach, a single `rgba(0,0,0,0.8)` full-screen scrim and existing close icon/touch target in the upper-right safe area. Title `Open in a space`; source creator avatar/name/public bio precede the choices, and each group/channel row shows name/type plus a brief community/moderation description underneath. Creator introduction and choices scroll while Close stays reachable; long bio cannot permanently displace the destinations. Keep one retained Feed underneath with no second VideoSurface, player, thumbnail fetch or media-URL route parameter. Native route background must be transparent, not a second opaque/double scrim. Underlying Feed controls, gestures and accessibility focus are unavailable while covered. No scrim-tap dismissal or swipe-to-dismiss by default; Close is the explicit exit.
16. **Overlay lifecycle and authority.** Capture exact originating publication/time/intentional-pause before opening. Coverage pauses playback and prevents hidden audio; repeated open/close must not reset position or turn a manual pause into autoplay. Keep the eligible retained frame (or its existing poster if the player releases) visible without creating another player; verify actual iPhone rendering rather than assuming native-stack transparency retains a frame. Closing resumes only when prior intent and current app/screen/auth/source eligibility allow it. Destination selection still resolves current exact authority, dismisses chooser and opens its matched publication; later Back returns to the original Global checkpoint. Loading, empty list and recoverable chooser error retain the close control and eligible origin backdrop. Source removal, identity reset or failed source verification masks an invalid backdrop with opaque unavailable state. Sign-in retains the current discard-old-intent policy; it cannot replay a stale selection after account replacement.
17. **Requirements are authoritative, separate entry state.** The later entry-workflow contract may expose only permitted introduction metadata and actual unmet requirements. Do not relabel a generic403 as age/payment/approval, derive restriction from a space name, or add placeholder checkout/verification buttons in this UI increment. Public viewing alone is not sufficient where a future authoritative policy requires joining before Follow. Requirements remain enforceable server-side; pending or expired membership cannot be bypassed by a direct Follow request, a Global source or a discovered space. Fulfillment never silently follows, charges, enrolls or grants personal access.
18. **One actual creator above all destinations.** Bind the shared introduction to the current Global source's displayed upload creator, using the existing public profile projection and visibility/show-bio rules. Match destinations to that same creator as well as the production, both when listing and resolving; production identity alone does not prove creator identity. Never substitute space owner or publication publisher. Missing/deleted source creator is unavailable, not a different creator's header. Broken/missing avatar gets the existing fallback; hidden/empty bio is omitted without fabrication. Snapshot display data is not authority and late profile/list results cannot cross source/account/visit boundaries. No Global Follow, personal-entry action or generic creator-wide Follow appears in this header.
19. **Real brief space descriptions.** Each eligible destination row renders its name, group/channel type and a short plain-text introduction supplied by its authorized owner/admin, describing community/topic and moderation culture. A description is invitation copy, not proof of enforcement or a substitute for actual entry requirements. Current Launch DTO has no description field and inspected spaces schema has no dedicated description column. During R2 verify existing authoring paths; if no canonical description exists, add optional bounded `settings.discoveryDescription` (max500 characters) with a small field in existing space settings and permission/CSRF checks. Merge only the validated field and preserve other settings. Return only its safe projection after normal destination authorization; do not send raw settings, private rules/moderation signals or inferred age/payment claims. Missing description has no invented substitute; retain the row and omit the empty text. Long descriptions wrap in scrollable content, with Close and destination action reachable. Later restricted-space introductions use their own explicit discovery permission, not today's feed authorization.



## API Contract

All native paths below are relative to `/api/viewer/v1`. Backend/native implementation and host/API/browser checks pass; physical acceptance remains Phase E.

| Method/path | Input | Success |
| --- | --- | --- |
| GET `/spaces/:spaceId/publications/:publicationId/creator-follow` | Canonical route IDs; no query/body fields |200 exact summary |
| POST same | No payload fields; server derives creator/follower |200 confirmed desired Follow state and summary |
| DELETE same | No payload fields; server derives creator/follower |200 confirmed desired unfollowed state and summary |

Summary: `{space:{id,name,type:'group'|'channel'},publicationId,creatorId,following,followersCount,canFollow,disabledReason:null|'self'}`. The adapter validates exact requested space/publication/expected creator and retains only these fields. Strings/counts are bounded and validated. Profile identity comes from the existing public Creator endpoint, not an expanded Follow response. `canFollow` describes availability of the toggle, including unfollow, rather than a personal-entry capability.

Legacy GET/POST/DELETE `/api/spaces/:id/users/:userId/follow?publicationId=N` retain `{following,followersCount}` and may add matching context/capability fields. Return the real self count while disabling self writes. This is an intentional legacy request tightening; an omitted publication no longer succeeds. Error defaults:400 `invalid_query`/`invalid_body`,401 `unauthorized`,403 `forbidden` or a dedicated allowlisted self-write code,404 `space_not_found`/`publication_not_found`/`creator_not_found`,503 `service_unavailable`. Establish exact safe mappings in Phase A; do not echo SQL, raw exception messages or private target metadata. Keep denial ordering from disclosing an inaccessible space's creator or count.
