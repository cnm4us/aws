### Scope

- Shared server enforcement for engagement in an explicit, currently viewable space and exact eligible publication; update the browser callers needed for that contract.
- Native Like/unlike, confirmed count/state and comment count; paginated top-level comment reading and creation, newest/oldest selection, explicit loading/empty/disabled/error states.
- Authorized personal, group and channel contexts. Personal uses existing explicit access; no follow/Global-derived grant. Public non-member spaces retain existing view authority and site-level comment permission, without introducing a membership-only participation rule.
- Context/account isolation, bounded verification and request lifecycle, keyboard/large-text behavior, playback/return regression, shared backend/browser tests, and a source-matched signed internal iPhone milestone.

Out of scope: native replies, comment edit/delete/moderation UI, liker directory, reactions beyond Like, new membership/follow/reporting workflows, notifications, ranking/reputation changes, analytics, subscriptions/payments, shared links/discovery expansion, CDN authorization, TestFlight/store release, broad legacy Jump hardening or a speculative cold-stall fix. Existing legacy reply reads/writes receive the shared authority/parent checks because leaving them weaker would bypass this boundary.

## Locked Decisions

1. **Explicit context on every engagement request.** Native paths carry space and publication IDs. Existing `/api/publications/:id/likes`, `/likes/users`, `/comments` and reply reads gain a required positive safe-integer `spaceId` query parameter, supplied by the browser's actual active non-Global context. Reject missing, malformed, repeated, unknown or mismatched context; never infer it from Global visibility or silently choose a destination. Update all in-repository callers together. This is a deliberate legacy engagement contract tightening; inventory non-Feed callers before changing services.
2. **Global stays discovery-only.** No native Global Like/Comment controls, counts, summaries, lists or writes; no engagement Global route. Deny Global/global-feed space aliases and settings representations at the shared service boundary. A group/channel publication also projected into Global remains engageable through its explicit authorized space context, even when the publication ID is identical. The server can validate the declared context; it cannot infer which screen an HTTP caller actually viewed.
3. **Authority is server-owned and request-specific.** Authenticate each request; load the exact space, reject Global aliases, assert current space view authority and require the exact publication in the ordinary space-feed selector, including members visibility/published/upload eligibility. Use the current principal only. Reads and writes share this policy across browser/native, including auxiliary liker/reply reads. Revalidate publication eligibility near mutation; do not hold a stale client capability as write authority. Hidden/nonexistent/mismatched publication returns a sanitized404 after the space check; denied space403 and invalid session401 remain distinct.
4. **Comment posting capability is separate from reading.** Existing visible comments remain readable when commenting is disabled. Posting requires `COMMENT_CREATE`, no applicable posting suspension under existing admin semantics, and current effective comments settings: space policy `off` or publication `comments_enabled=0` disables new posts; `on`/`inherit` do not override an explicit publication off. Existing publish-time defaults remain unchanged. A denied composer returns `canComment:false` plus a safe reason in reads; post rechecks and returns a specific403. No new membership/subscription purchase requirement. Disabled posting must not sign out or revoke otherwise valid feed viewing.
5. **Publication-scoped data.** Reuse publication likes/comments; never aggregate by production or share cache state across spaces. Distinct publications of the same production keep separate counts/threads. Like/unlike are idempotent desired-state operations, one in flight per context/publication. Serialize supported mutations consistently and commit engagement row plus count atomically on one connection; rollback on error. Do not silently recount or repair historical data. Native uses server-confirmed state/count, with a pending indicator and useful failure message.
6. **Minimal safe display data.** Native comment rows allow only `id`, `body`, `createdAt`, author `{id,displayName}` and `isMine`; wrap with exact `spaceId`/`publicationId`. Use a neutral display fallback, never email. No storage keys, credentials, membership/moderation metadata or hidden/deleted bodies. Remove email output/fallback from touched browser engagement serializers too, updating their existing presentation fallbacks. Author navigation from comments and liker discovery are deferred.
7. **Top-level first.** Native creates only top-level plain-text comments, trim and require1–2000 UTF-16 code units consistently on client/server, preserving internal newlines. No HTML rendering, Markdown interpretation, attachments or `parentId` acceptance. Existing replies remain stored; native label/summary must distinguish total visible comments (including replies) from the top-level list. Count remains reply-inclusive while the native list shows top-level rows. The user explicitly requested removal of the explanatory count-scope and end-of-list footer messages; keep these semantics in the API/docs without claiming every counted row is shown. Legacy reply operations require an existing visible, nondeleted parent in the exact publication, and reject cross-publication or unsupported nesting. No new native reply/delete routes.
8. **Paging and memory are bounded.** Comment pages default20,max50; newest default and explicit oldest support, deterministic createdAt/ID keyset. Validate all query grammar; native cursors bind version/space/publication/user/order and expose no private author IDs or bodies. Treat cursors as positions, never capabilities. Deduplicate IDs and reject cursor loops; keep at most200 loaded native rows, then offer Refresh rather than unbounded accumulation. No realtime polling of every loaded page or hidden publication.
9. **Comment delivery uncertainty is explicit.** Disable duplicate Send while pending; no automatic retry/queue, including on foreground or reconnection. A timeout/cancel may occur after the server committed. Keep the draft on a definite failure; for an ambiguous outcome show that the comment may have posted, refresh/read before deliberate resend, and never claim abort rolled it back. Successful201 returns the created row/ID and updated summary; clear the matching draft only. Exactly-once retry across disconnects is not promised by this schema; durable idempotency is deferred.
10. **Native presentation.** Space rail order: Creator, Like/count, Comments/count, CC when available, sound. Global remains Creator, Launch, CC, sound. Reuse owned icons/44-point touch targets and the current control lane; selected Like uses a filled heart and an accessible selected state, unselected an outline. Counts are noninteractive on Like; Comments icon/count share one action. Reach all controls via the existing rail scroll at constrained heights; do not shrink targets or overlap captions/recovery. A disabled/unavailable count is not fabricated as zero.
11. **Comments owns a covered route, not a new feed.** Open a full-screen Comments route with a dark translucent scrim over the existing paused Feed after exact access verification. Checking, background, denial and expiry use an opaque mask. Per the user’s phone layout correction, omit the Comments title, use a fixed44-point square × close control with accessible Close comments label, omit the duplicate space title and use a centered N Comments/Oldest selector with a chevron and a scrolling overlay containing Newest/Oldest radio choices. Newest is the default and displays N Comments; Oldest displays Oldest. The authorized scrim is80% black. Enlarge the composer layout vertically when needed. Use a single bounded route containing IDs/context generation, no media/token/page payload. Covering pauses playback without changing intentional pause; captions/story are hidden. Close dismisses keyboard and returns to the exact feed/video/time with its prior pause state after required access validation. No autoplay from Send, sorting, failure or background return. Draft is in memory for this one visit; closing discards it, never moves it to another publication/account.
12. **Verification and failure scope.** Comments screen must independently validate account plus exact publication on entry/foreground and renew quietly at45s within a hard60s request-start verification age, using the existing `VerifiedRefresh` controller. While covered Feed has released routine ownership, Comments claims it; no duplicate provider clock or second feed request owner. Healthy renewal keeps comments/draft stable. Failure/expiry clears protected rows/draft, disables writes, ignores late success and requires explicit recovery. Return to Feed uses its existing blocking revalidation. Rail summary failures need local Retry without pausing valid playback; definitive401 invalidates identity, definitive space/publication denial clears protected engagement and tells the current feed owner. `comments_disabled`/`comment_forbidden` only affect composing. Never turn a generic mutation503 into a proven permission denial.
13. **Race and lifecycle safety.** Key all state by API origin, auth generation, space, publication and visit/request generation. Abort/ignore on close, blur, selection, Refresh, context change, background, identity replacement and sign-out. A write may commit after navigation; its result must not update a new screen, restore a cleared draft, reactivate an old account or replay audio. Re-fetch authoritative counts on revisit/Refresh and after uncertain writes. No persistent comment-body storage or production logging of comment bodies/tokens.
14. **Distribution and evidence.** Preserve three-player budget, quiet renewal, Launch outer root and Creator inner root. No product source/build change during this planning task. At execution choose the next available iOS build number (expected11), stamp actual source, verify export/archive/downloaded artifact and install over build10. Record physical versus controlled coverage separately. Commit/push requires a request for the resulting new work; the prior completed delivery request does not automatically publish this plan or future implementation.

## Proposed API Contract

All paths below are relative to `/api/viewer/v1`, authenticated, no-store and strictly validated. Cookie callers retain existing CSRF requirements for unsafe methods; native sends bearer only with `credentials:omit` and existing HTTPS/mixed-auth rules.

| Method/path | Request | Response |
| --- | --- | --- |
| GET `/spaces/:spaceId/publications/:publicationId/engagement` | No body or query | Exact IDs, `likes:{count,likedByMe}`, `comments:{count,hasCommentedByMe,canComment,disabledReason}` |
| POST `/spaces/:spaceId/publications/:publicationId/like` | No payload fields | Exact IDs and confirmed `likes:{count,likedByMe:true}` |
| DELETE `/spaces/:spaceId/publications/:publicationId/like` | No body | Exact IDs and confirmed `likes:{count,likedByMe:false}` |
| GET `/spaces/:spaceId/publications/:publicationId/comments` | `limit`,optional `cursor`,optional `order=newest\|oldest` | Exact IDs, sanitized top-level `items`, `nextCursor`, comment summary/capability |
| POST `/spaces/:spaceId/publications/:publicationId/comments` | Exact JSON `{body:string}` | 201, exact IDs, sanitized created `item`, confirmed comment summary |

- Counts are nonnegative safe integers. `hasCommentedByMe` reflects visible/nondeleted comments, not hidden/deleted historical rows. Do not reuse the feed's unfiltered EXISTS flag as authoritative.
- Read `disabledReason` is null or an allowlisted value such as `comments_disabled`/`comment_forbidden`. Rejection uses `invalid_body`400, `invalid_query`400, `unauthorized`401, `forbidden`403, `publication_not_found`404, `comments_disabled`403, `comment_forbidden`403, `request_too_large`413 or sanitized `service_unavailable`503. Unknown server details never reach UI.
- Native comment JSON gets an exact-route16KiB parser bound before the general parser, strict content type and object/key validation. Preserve safe parser failures without body logging. Apply equivalent strict scalar/body/parent validation to touched legacy endpoints while preserving their successful cookie-auth flow.
- Keep legacy successful count/list shapes where compatible, except intentional email removal and required space context. Make browser requests pass context for summary, write, liker pagination, comment pagination and legacy replies. Global browser must issue no engagement requests. Native bearer remains rejected by cookie-only legacy routes.
- This contract is proposed behavior. Existing services and DTOs do not yet satisfy it. Final names may change during Phase A if ownership stays narrow and all callers/tests/docs agree.
